# ADR 002. H2 в интеграционных тестах вместо Testcontainers

## Контекст

Требуются интеграционные тесты CRUD, каскадов, ограничений и HTTP-слоя. Варианты:
Testcontainers с PostgreSQL или встроенная H2.

Допускается оба варианта: «используется H2/Testcontainers».

## Решение

Тесты на H2 в режиме PostgreSQL:

```
jdbc:h2:mem:coursehub;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1
```

Профиль `test`, `ddl-auto=create-drop`, демо-данные отключены.

## Последствия

Плюсы:

- `mvn verify` работает без Docker, на любой машине при проверке;
- тесты быстрые: 42 теста примерно за 6 секунд;
- нет конфликтов портов и образов.

Минусы:

- H2 не повторяет поведение PostgreSQL на 100%: свои планы запросов, свои типы,
  свои сообщения об ошибках. Нативный SQL и специфичные функции не используем,
  поэтому риск ограничен;
- `jsonb`, `array`, оконные функции и партиционирование так не проверить.

## Что бы изменилось при росте проекта

Добавился бы профиль `it-postgres` на Testcontainers и запуск обоих наборов в CI.
Ключевые сценарии остались бы на H2 для скорости, а PostgreSQL-специфичные запросы
проверялись бы отдельно.
